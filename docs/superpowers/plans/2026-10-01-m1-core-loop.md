# M1 Core Loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A GPU-free, end-to-end AutoResearch loop that any agent can drive through ten operations. Approvals, sealed evaluation, budgets and CI-gated keep/discard are all enforced by the server.

**Architecture:** One SQLite database holds campaigns, experiments, stage runs, results, approvals, tokens and an event log. Rows are versioned, and writes are idempotent. A worker advances experiments one effect per tick:
- launch the next stage through an executor;
- observe it;
- on exit, seal the outputs, verify them, and record the decision.

A service layer holds the rules. FastAPI exposes the service layer. The CLI and the MCP server are thin HTTP clients, so no client can bypass server checks.

**Tech Stack:** Python 3.12, pydantic v2, FastAPI, uvicorn, httpx, psutil, mcp (Python SDK), SQLite (stdlib), pytest.

**Spec:** `docs/ARCHITECTURE.md`; design rationale is in the maintainer's plan (not in this repo).

## Global Constraints

- Python `>=3.12`.
- Rules are enforced in the service layer, never in prompts or hooks.
- Agent tokens can only *request* `start`, `budget`, `promote` and `publish`. Human tokens grant them. A human may also act directly.
- Every model is `FrozenModel` (`extra="forbid"`, `frozen=True`). Hashes use `canonical_hash`: sorted-key compact JSON, then sha256.
- Infrastructure failure produces `incomplete`, never a smaller denominator.
- Smoke-scope evidence is labelled `smoke` everywhere. `promote` and `publish` refuse smoke results.
- Lint and format: ruff + black, line length 100. Tests run with `uv run pytest`.

## Review Focus

1. **Worker restart while a stage is running.** The run must be rediscovered from its run directory and adopted, not relaunched. Test in Task 6/8.
2. **A candidate evaluated on a different task set than the incumbent.** This must be rejected as an evaluation error, never compared. Test in Task 2.
3. **An agent token calling a grant endpoint.** Must get 403 and leave no state change. Test in Task 5/9.
4. **The same `propose` retried with the same idempotency key.** Must create exactly one experiment. Test in Task 3/7.
5. **An evaluator script edited after registration.** The launch must be refused because the stored sha256 no longer matches. Test in Task 6/8.

### Task 2: Statistics and decision rules

**Files:**
- Create: `src/bashgym_autoresearch/stats.py`, ported verbatim from BashGym `eval/stats.py`: `BootstrapResult`, `paired_bootstrap`.
- Create: `src/bashgym_autoresearch/decision.py`.
- Test: `tests/test_stats.py`, `tests/test_decision.py`.

**Interfaces (produces):**
- `paired_bootstrap(deltas, clusters, *, n_resamples, alpha, seed) -> BootstrapResult`.
- `Comparison(decision: Decision, improvement: float, ci_low: float, ci_high: float, breached_gate: str|None, reason: str)`.
- `decide(spec, *, role, incumbent: EvalEvidence|None, result: EvalEvidence|None, crashed: bool) -> Comparison`.
  - `crashed` → `crash`.
  - `result.complete` is False → `incomplete`.
  - baseline → `baseline`.
  - Different task-id sets → `EvaluationMismatch`.
  - Otherwise deltas are oriented by direction:
    - a breached protected gate → `discard`;
    - `ci_low > 0 and ci_low >= minimum_improvement` → `keep`;
    - `ci_high < minimum_improvement` → `discard`;
    - anything else → `inconclusive`.
- `NextAction(kind: Literal["await_start","wait","propose_baseline","propose_candidate","stop"], reason: str)`.
- `next_action(spec, status, *, has_baseline, running, experiments_counted, cost_used, best_value, now) -> NextAction`.
  - Evaluation order: status, then `running`, then deadline, `max_experiments`, `max_cost`, `target`, then baseline/candidate.
- `validate_change(role, change: Change|None)`: baseline requires `None`; a candidate requires exactly one change with `before != after`.

**Steps:**
- [ ] Port the stats tests: a significant positive shift, zero effect, cluster resampling, and validation errors.
- [ ] Write decision tests, one per branch, including:
  - a minimize-direction inversion;
  - a CI straddling zero → `inconclusive`;
  - a gate breach overriding a gain;
  - a mismatched task set raising;
  - `next_action` ordering for each stop rule.
- [ ] Implement.

### Task 4: Sealing and evidence verification

**Files:**
- Create: `src/bashgym_autoresearch/seal.py`, `src/bashgym_autoresearch/evidence.py`
- Test: `tests/test_seal.py`, `tests/test_evidence.py`

**Interfaces (produces):**
- `Sealer(key: bytes>=32)`:
  - `seal(run_dir: Path, *, identity: dict) -> SealManifest`: hashes every file under `run_dir/outputs`, then writes `seal.json` with an HMAC over the canonical manifest.
  - `verify(run_dir, *, identity) -> SealManifest`: checks the signature, the identity, the exact file set and the hashes.
  - `SealError` is raised on any failure.
  - Ported and simplified from BashGym `campaigns/artifacts.py`: no temp→sealed rename, because the run directory is already unique.
- `EvalContext(campaign_id, experiment_id, suite_id, dataset_sha256, evaluator_sha256, model_digest)`; its `digest()` is `canonical_hash`.
- `write_context(path, ctx)`.
- `read_evidence(outputs_dir, ctx) -> EvalEvidence`:
  - requires `evaluation.json`, at most 4 MB;
  - `context_sha256` must equal `ctx.digest()`;
  - raises `EvidenceError`.
- `directory_digest(path) -> str`: sorted `(relpath, sha256, size)` items, then `canonical_hash`.

**Steps:**
- [ ] Write tests:
  - a seal round-trip;
  - a tampered file, an extra file, a wrong key and an identity mismatch each fail;
  - evidence with the wrong context digest fails;
  - an oversized file fails;
  - `directory_digest` is stable across file creation order.
- [ ] Implement.
- [ ] Run the tests and see them pass.
- [ ] Commit: `feat(seal): HMAC sealing and evaluation evidence verification`.

### Task 6: Executors

**Files:**
- Create: `src/bashgym_autoresearch/executors/__init__.py`, `executors/base.py`, `executors/local.py`, `executors/_wrapper.py`
- Test: `tests/test_local_executor.py`

**Interfaces (produces):**
- `RunState = Literal["running","exited","lost"]`.
- `Observation(state, exit_code: int|None)`.
- `Executor` protocol:
  - `launch(run_id, run_dir, argv, env) -> None`
  - `observe(run_id, run_dir) -> Observation`
  - `kill(run_id, run_dir) -> None`
- `LocalExecutor`:
  - `launch` creates the run directory exclusively (`FileExistsError` if it exists), then runs `python -m bashgym_autoresearch.executors._wrapper <argv...>` in a new process group/session.
  - The wrapper writes `pid.json` (pid plus psutil `create_time`), streams the child's output to `stdout.log`/`stderr.log`, and writes `exit_code` atomically (tmp file + `os.replace`).
  - `observe`: an `exit_code` file means `exited`; a live pid with a matching `create_time` means `running`; otherwise `lost`.
  - `kill` kills the process tree via psutil.

**Steps:**
- [ ] Write tests:
  - a successful command reports `exited`/0 with captured stdout;
  - a failing command reports its exit code;
  - a sleeping command reports `running`, then `kill` makes it `exited`/`lost`;
  - a relaunch into an existing directory raises;
  - a fresh `LocalExecutor` instance observes an existing run (restart adoption).
- [ ] Implement.
- [ ] Run the tests and see them pass.
- [ ] Commit: `feat(executors): restart-safe local executor`.

### Task 7: Service layer (the rules)

**Files:**
- Create: `src/bashgym_autoresearch/service.py`
- Test: `tests/test_service.py`

**Interfaces (produces):** `Service(store, sealer, home: Path, clock=utcnow)`.

| Method | Behavior |
|---|---|
| `register_profile(principal, profile)` | Human only. Hashes `script`, stores the profile, and refuses if the sha differs from the declared value. |
| `create_campaign(principal, spec, idem)` | Human only. Status starts at `awaiting_start`. |
| `request_approval(principal, campaign_id, kind, payload, idem) -> approval` | Any role. |
| `decide_approval(principal, approval_id, grant: bool)` | Human only. Granting `start` sets status `running`; granting `budget` raises `max_cost` by `payload.amount`; `promote`/`publish` refuse when the target is smoke-scope. |
| `set_guidance(principal, campaign_id, text)` | Human only; bumps `guidance_version`. |
| `propose(principal, campaign_id, role, change, recipe, hypothesis, estimated_cost, idem) -> experiment` | Requires status `running` and no queued/running experiment. `next_action` must allow the role. Calls `validate_change`. A candidate's parent is the current incumbent. Rejects proposals that would exceed `max_cost`. |
| `brief(principal, campaign_id) -> dict` | next_action, status, incumbent and its value, the last 5 results with CI, budget used/remaining, guidance + version, pending approvals, and the smoke label. |
| `results(principal, campaign_id) -> list[dict]` | All results. |
| `failures(principal, campaign_id) -> dict` | Latest crashed/incomplete stage: exit code, last 4 KB of stderr, and the stage name. |
| `pause` / `resume` / `cancel(principal, campaign_id)` | `resume` from paused only; `cancel` is terminal. |
| `report(principal, campaign_id) -> dict` | Full ledger: experiments, changes, decisions, CIs, the final incumbent, and the smoke label. |
| `wait(principal, campaign_id, after_seq, timeout_s) -> dict` | Polls events. |

**Steps:**
- [ ] Write tests:
  - an agent cannot create a campaign, decide an approval or set guidance (Forbidden), and none of those attempts changes state;
  - `propose` before the start grant is refused;
  - a duplicate idempotency key returns the same experiment;
  - a second `propose` while one is running is refused;
  - a baseline-with-change is refused;
  - the budget limit is enforced and a granted budget approval raises it;
  - `brief` contents are correct;
  - `promote` of a smoke result is refused.
- [ ] Implement.

### Task 8: Worker loop

**Files:**
- Create: `src/bashgym_autoresearch/worker.py`
- Test: `tests/test_worker.py`

**Interfaces (produces):** `Worker(service, executor)`, with `tick() -> str` (a description of the single effect taken) and `run(stop_event, interval)`.

`tick` takes the first applicable effect, in this order:
1. **Observe a running stage.**
   - Past its deadline → kill it and mark the experiment `incomplete`.
   - `exited` 0 → seal it (identity: campaign/experiment/stage), then:
     - train: record `model_digest = directory_digest(outputs/model)`;
     - evaluate: `read_evidence` → `decide` → store the result and set the experiment to `evaluated`.
   - `exited` non-zero → `crashed`.
   - `lost` → `incomplete`.
2. **Launch the next stage of a queued/running experiment** (train if the campaign has `train_profile` and the role is candidate, then evaluate).
   - Before launch, the profile's script sha256 is re-verified; a mismatch makes the experiment `incomplete` with a `script_changed` reason.
   - Writes `inputs/context.json` (EvalContext) for evaluate stages and `inputs/recipe.json` for all stages.
   - Uses run id `sha256(experiment_id:stage)[:24]`.
3. **Enforce stop rules:** status `exhausted` or `completed`, with an event.
4. **Idle.**

**Steps:**
- [ ] Write tests with tiny Python stage scripts written into `tmp_path`:
  - baseline evaluate → `baseline`;
  - candidate train + evaluate → `keep`;
  - an equal-score candidate → `inconclusive`;
  - a crashing train → `crash`;
  - a timeout → `incomplete`;
  - an edited eval script → `incomplete` (`script_changed`);
  - a worker restarted mid-stage adopts the run instead of relaunching it (assert a single launch);
  - `max_experiments` reached → `exhausted`.
- [ ] Implement.
- [ ] Run the tests and see them pass.
- [ ] Commit: `feat(worker): one-effect-per-tick experiment loop`.
